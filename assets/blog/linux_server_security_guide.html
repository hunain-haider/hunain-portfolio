Linux Server Security: Initial Hardening for Ubuntu 24.04 LTS

Hunain
• Updated Guide • 5 min read • Production Tested
The 10-Minute Exposure Window

The moment a new public cloud VPS goes online, automated scanners and crawler bots start probing its IP address within minutes. These bots run automated password dictionaries against root.

The Solution: In this quick walkthrough, we will establish baseline protection: creating an isolated sudo user, disabling password attacks with Ed25519 SSH keys, configuring the UFW firewall, and setting up Fail2ban intrusion blocking.

1 Create a Sudo User

Direct root access is an open liability because every automated scanner defaults to guessing its credentials. Adding an administrative user keeps all operations audited under an explicit identity in /var/log/auth.log.

CODE 
# Log in as root, then create user Hunain with sudo privileges
adduser Hunain
usermod -aG sudo Hunain

2 Set Up Ed25519 SSH Key Authentication

Password-based logins are inherently prone to brute-force dictionaries. Modern Ed25519 elliptic-curve cryptography offers robust collision resistance, small key footprints, and faster signature verification than legacy RSA keys.

1. Generate the key pair on your personal machine:

CODE 
# -a 100 increases Key Derivation Function (KDF) rounds against offline decryption
ssh-keygen -t ed25519 -a 100 -f ~/.ssh/id_ed25519_myserver

2. Install the public key on the server (as user Hunain):

CODE 
mkdir -p ~/.ssh && chmod 700 ~/.ssh
nano ~/.ssh/authorized_keys   # Paste your public key file contents here
chmod 600 ~/.ssh/authorized_keys

3. Verify the key login works from your local terminal:

CODE 
ssh -i ~/.ssh/id_ed25519_myserver Hunain@<SERVER_IP>

3 Harden the SSH Daemon

Now that key authentication is verified, configure /etc/ssh/sshd_config to disable password fallback entirely and reject remote root requests.

CODE 
# Disable root SSH access
PermitRootLogin no

# Force key-only login (disable password prompts)
PasswordAuthentication no

# Restrict login specifically to Hunain
AllowUsers Hunain
AllowGroups sudo

# Modern Key Exchange Algorithms
KexAlgorithms curve25519-sha256,diffie-hellman-group-exchange-sha256

Restart the daemon to apply settings:

CODE 
sudo systemctl restart ssh
Tip: Keep your current terminal session open until you confirm a new login succeeds in another tab.

4 Configure UFW Firewall

Ubuntu includes ufw (Uncomplicated Firewall) to manage iptables/nftables packet filtering. Deny all unsolicited incoming connections while keeping designated application ports reachable:

CODE 
# Set baseline traffic rules
sudo ufw default deny incoming
sudo ufw default allow outgoing

# Permit SSH (port 22 or your custom port)
sudo ufw allow ssh

# Allow standard web traffic
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# Enable firewall rules and check status
sudo ufw enable
sudo ufw status verbose

5 Install and Configure Fail2ban

Fail2ban dynamically monitors server authentication logs. If an IP triggers repeated authentication failures, it gets dropped by the firewall for an hour.

CODE 
# Install Fail2ban package
sudo apt update && sudo apt install -y fail2ban

# Configure custom SSH jail override
sudo tee /etc/fail2ban/jail.local > /dev/null << 'EOF'
[sshd]
enabled = true
port = ssh
maxretry = 3
bantime = 3600
findtime = 600
EOF

# Restart and inspect status
sudo systemctl restart fail2ban
sudo fail2ban-client status sshd

✓ What These Steps Protect Against

Here is a breakdown of common attack vectors and the defensive layers you just configured:

Threat Vector Applied Defense Security Impact
Brute-Force SSH Logins Ed25519 Keys + Fail2ban Bans attacking IPs after 3 attempts
Root Compromise via SSH PermitRootLogin no Shuts off default target accounts
Port Probing & Discovery UFW Firewall (deny incoming) Blocks unmapped port exposure
Credential Stuffing User Hunain + Key Auth Passwords are never evaluated

7 Next Steps

With baseline security established, your server is ready for applications. Consider implementing these next layers:

  • Enable automatic security updates (sudo apt install unattended-upgrades)
  • Configure Cloud Provider Security Groups as an outer perimeter layer
  • Set up private VPN access (WireGuard or OpenVPN) for internal tools
  • Automate periodic off-site encrypted backups
